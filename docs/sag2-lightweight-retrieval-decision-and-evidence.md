# SAG2 与轻量检索：调研核查和实施决策

日期：2026-11-08。性质：静态源码核查与方案建议；尚未实现、运行基准或验证端到端行为。具体算法、迁移、评测与交互设计分别见 [无向量检索可行性](sag2-embedding-free-retrieval-feasibility.md) 和 [证据评估与界面设计](sag2-evidence-evaluation-and-ui-design.md)。本文件作为决策入口，避免另建一套与既有设计冲突的方案。

## 结论

**建议增加免 embedding 建库和检索能力，先交付完全本地的词法快搜，再以实验功能验证 SAG2 风格的多跳证据检索；保留现有混合检索。** 两者满足不同需求：词法快搜不需要模型；多跳证据评分可使用远程 Jev 或尝试本地重排，仍有查询计算成本。普通重排器的相关性评分不能假定等价于 Jev 的上下文证据判断。生成回答另需模型。是否默认启用证据扩展应由本项目数据与目标设备上的对照试验决定。

本建议默认面向中文技术笔记、个人电脑及低功耗设备，设备型号、可用内存、离线要求和目标规模尚未由用户指定。以下预算是实验起点，不是性能承诺。研究范围不包括实现代码、安装依赖、读取用户知识库正文作评测或向外发送内容。

## 方案比较与取舍

| 路线 | 建库 / 查询依赖 | 长处 | 欠缺及判断 |
| --- | --- | --- | --- |
| A. 本地词法快搜 | 解析、分块、FTS5；查询无需 embedding 或评分模型 | 最低运行依赖；标识符、错误码等精确匹配可控 | 同义词、跨语言、首跳未命中较弱；推荐首阶段 |
| B. SAG2 风格证据扩展 | A 的索引；查询时证据评分与有限轮词项召回 | 跨文档桥接可能改善多跳证据覆盖 | 多次检索及评分增加延迟、成本与漂移；首跳无桥梁时仍会失败；作为可选实验 |
| C. 现有混合检索 | embedding、BM25，可选重排与图谱 | 语义与精确匹配互补 | 模型推理和索引开销较高；保留作为质量对照及常规选项 |
| D. 独立运行 SAG-Wiki | 独立 Rust 程序和索引；深搜依赖 Jev | 可用于外部对照和学习 | 额外进程、部署、权限及索引同步；本项目已有基础，不建议默认依赖 |
| E. GraphRAG 类图摘要 | 抽取、图构建及摘要可能依赖模型 | 擅长某些全局主题问题 | 与本项目文档链接图及 SAG2 查询时扩展不同；构建成本更高，不适合作为轻量默认。参见 [Microsoft GraphRAG](https://github.com/microsoft/graphrag) |

可研究的现有库：首先复用 SQLite FTS5 与 jieba.NET；如实测发现过滤、分词或规模瓶颈，再做 [Lucene.NET](https://github.com/apache/lucenenet) PoC，评估额外索引一致性和迁移成本。其仓库注明 4.8 处于 beta，版本与目标运行时兼容性应在实施时再次核实。[Haystack 的混合检索示例](https://docs.haystack.deepset.ai/docs/3.3/advanced-rag-agent) 可参考 BM25、向量和 RRF 的组合方式，无须为此引入 Python 服务。SAG-Wiki 本地 `LICENSE` 为 MIT；移植代码前保留声明，并分别核查依赖、模型与基准数据许可。

## 推荐设计

将**索引能力**和**查询策略**分开配置：文档与词法索引始终可独立使用，向量索引可选；查询选择 Lexical、Evidence 或现有 Hybrid。明确显示实际策略和降级原因。已有配置、外部接口和默认行为保持兼容；不得自动删除既有向量。

1. **索引入口**：抽离文件与 chunk 的原文存储职责，先用现有 SQLite 实现的兼容适配器；免向量路径不得初始化或调用 embedding 模型/tokenizer。建立内容版本和索引就绪状态；补向量仅处理缺失或过期版本。
2. **检索入口**：在任何 embedding 调用之前按策略分流。词法路径执行范围约束后召回，按 chunk ID 批量取回原文与来源；不要把预分词文本直接当作引用。过滤应在每一轮、外发评分前及最终返回时有效，避免范围外数据泄漏或 Top-K 后过滤造成召回不足。
3. **多跳策略**：首轮 BM25 → 按问题和已有证据评分 → 筛选多样化种子 → 提取词项 → 范围内检索、交错去重 → 重新评分。保留初轮结果；限制轮数、候选、评分批次和总耗时。无新增证据、取消、预算耗尽时停止；索引变化时中止并提示重试，或在一致快照上完成，不混合不同版本。
4. **模式应用**：复用搜索策略及工厂承载 Lexical/Evidence；用适配器接 Jev 专用协议和既有 reranker，标明各自评分语义；扩展现有状态机报告检索、评分、扩展、完成及失败，循环由 hop 和预算控制。只在确有多个实现或测试边界需要时新增接口，避免抽象层叠加。
5. **失败与隐私**：评分超时或不可用时按调用方策略明确降级为已过滤的词法结果；取消不得伪装为成功。远程评分会发送问题和候选原文，需明确按源允许外发、限制超时并避免在日志记录正文和密钥。

索引一致性是交付前置条件：先核实文档、FTS、图谱和向量各自连接与事务；若无法同事务提交，使用 staging + active version 原子切换，并设计崩溃恢复。更新、重命名、删除、停用和重分块均需使旧内容、旧向量不可混入当前版本。升级前备份，兼容性不足时以备份恢复，而不是假设旧版可读取新 schema。

## 性能与实验决策

免 embedding 预期节约建库推理与模型驻留，但解析、分词、图谱、磁盘和 SQLite 仍占资源；证据扩展则可能显著增加查询耗时。本地低功耗 CPU、远程评分与纯词法必须分开记录，不能把远端算力成本归零。中文切词、短词、C# / .NET、路径、版本号、否定、跨语言和无答案均是重点风险。SQLite trigram 对少于三个 Unicode 字符的全文查询有局限，不宜当作中文分词的直接替代。

试验起点：首轮 30–50 候选、3–5 种子、5–10 个扩展词、最多 1 轮、总候选 60 和 5 秒预算；它们是待验证参数，不能作为发布 SLA。将评分、索引和回答的成本分别记录。

建立按文档或主题隔离的标注集，冻结测试集，避免调参或标签泄漏。相同语料、切块、过滤条件和 Top-K 下比较：A 词法、B 词法 + 本地重排、C B + 1 跳、D Jev 0/1/2 跳、E 现有混合；可另比较混合加扩展。报告 Recall@K、完整证据覆盖 AE@K、nDCG/MRR、来源与行号准确性及无答案错误；按题型、样本数和置信区间报告，不能只看均值。记录冷/热启动、索引吞吐与大小、峰值内存、CPU、p50/p95/p99、模型加载、评分请求与费用，同时说明硬件、线程和缓存。作者在 [SAG2 基准](https://github.com/Zleap-AI/SAG-Benchmark/blob/main/sag2/README.md) 给出的结果属于其特定数据和预算，MuSiQue 参与方法开发；不能外推到本项目中文笔记或低功耗设备。

## 实施顺序和验收门槛

- **P0 基线与边界**：核查入口、存储与事务；建立无网络、无 embedding 文件的自动化测试及可恢复数据库副本。准确记录现有模式质量与设备性能。
- **P1 词法模式**：原文与词法独立建库、路由、范围过滤和引用；验收建库与搜索 embedding 调用数为零，离线启动、增量更新、删除、重启均正确，禁用或范围外内容不进入结果与候选。
- **P2 证据模式**：先以本地重排器实验，再按真实 Jev 协议接入；验证取消、超时、乱序、索引更新及明确降级。只有在冻结测试集上完整证据覆盖有可复现收益且延迟/资源满足实际设备目标时，才扩大使用；否则保留实验或不启用。
- **P3 可选混合**：增量补向量与受控融合；比较收益、覆盖率和故障恢复。功能开关关闭时恢复旧策略，数据库迁移及回退先在副本演练。
